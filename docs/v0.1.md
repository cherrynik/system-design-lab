# v0.1 — Path existence

## Goal

Prove the smallest useful vertical slice of the product: a user edits a system-design graph and a deterministic evaluator explains whether it satisfies one requirement.

## Exercise

Connect a `Client` to a `Service`.

The solution is valid when at least one directed path exists from any client node to any service node. Intermediate nodes are allowed, so both examples pass:

```text
Client -> Service
Client -> Load Balancer -> Service
```

## User flow

1. Open the exercise.
2. See the requirement and an editable graph.
3. Add, connect, or remove nodes.
4. Select **Validate architecture**.
5. See a structured `PASS` or `FAIL` result with an explanation.

## Included

- Three component types: `Client`, `Load Balancer`, and `Service`.
- Directed nodes and edges.
- A generic graph reachability check.
- A Go evaluator with unit tests.
- One HTTP evaluation endpoint.
- A React Flow canvas and validation panel.

## Not included

- Users, authentication, persistence, or billing.
- Capacity, latency, RPS, availability, or failure simulation.
- Deployment, infrastructure generation, or load testing.
- Scoring, AI evaluation, or reference-topology matching.

## Acceptance criteria

- `Client -> Service` passes.
- `Client -> Load Balancer -> Service` passes.
- A disconnected client and service fail.
- Reversed edges fail.
- Cycles do not hang the evaluator.
- Removing an edge in the UI changes the next validation result.
